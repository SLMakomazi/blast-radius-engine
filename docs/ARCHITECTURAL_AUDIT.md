# Architecture audit before cleanup

Baseline: main at `2360328` (`fix: stabilize Stage 2-4 E2E validation runners`).
Main was pulled and clean before creating `refactor/ddd-repository-cleanup`.
No production source had been moved when this audit was written.

## Existing design

Four independent Java 21 / Spring Boot 4.1.1 Maven projects, each with its own Docker context. No root Maven reactor or wrapper. The API uses JDBC/Flyway and springdoc; mock services use validation, Micrometer, bounded HTTP clients and (document only) JDBC/Flyway. React/Vite displays persisted analysis; Python drives synthetic traffic and acceptance tests. Docker Compose has 12 services, two independent databases, retained topology in a named volume, direct metrics scraping and asynchronous OTLP logs/traces.

Domain models have Java-only imports. Seven ports describe external needs using domain types. Telemetry adapters sanitize provider data before evidence construction. Analysis coordinates deterministic graph/severity/containment rules. Lifecycle persists sanitized JSON; a scheduler detects failures and requires fully covered healthy windows for recovery. Optional Gemini and deterministic fallback explain evidence.

## Proposed minimal moves

Keep `service` as the application layer. Move only the three pure rules to existing domain subpackages, the fallback to `adapters.ai`, the scheduled entry point to `adapters.scheduling`, and the analysis request to `api.dto`. Move matching rule tests. Existing root component scanning covers these destinations; bean names, constructor signatures, configuration keys and JSON fields stay the same. Update imports, same-package references and docs.

Do not rename established classes. Keep adapter-specific configuration beside its provider and OpenAPI configuration at the API boundary. Keep the stored JSON mapper in the application layer: it maps a persisted analysis for a use case, rather than implementing storage. Keep domain diagnosis records: they are provider-neutral port contracts, not Gemini DTOs. Keep all mock services simple.

## Findings and deferred debt

- `service` mixes orchestration, pure domain rules, a port implementation and a scheduled entry point.
- API request and nested response records lack one explicit DTO convention. Proposed convention: `api.dto`; nested response extraction can be a separate small step after the first moves pass.
- Controllers read repository/topology ports directly; an application query facade would improve consistency but is a separate behavior-sensitive change.
- Lifecycle policy remains inside the scheduler. Moving it without splitting behavior is safer here; extracting policy needs dedicated lifecycle coverage.
- Analysis contains lab marker and metric-name interpretation. Keep those semantics because Stages 1–4 depend on them; future policy extraction needs its own design and regression suite.
- Generic exceptions are classified by message prefixes. Preserve text because monitor/controller behavior depends on it; typed errors are future debt.
- Some timeout properties are not applied independently; shared HTTP timeouts are wired in TelemetryAdapterConfig. No timeout changes in this cleanup.
- `RetainedTopologyProvider` uses a discovery helper constructed with a null telemetry provider; separating the pure mapper is future debt.
- Repeated DTOs and correlation filters in mock modules are intentional: each builds independently, without a shared runtime library.
- No dead Java class was proven. TraceDiscoveredTopologyProvider remains used by retention, tests and offline replay. Experiment types remain used by analysis, API and tests.
- Placeholder-only directories: docker, infrastructure/failure-driver, fixtures/experiments, fixtures/incidents, fixtures/topology, fixtures/telemetry/{health,logs,metrics,traces}. No tracked runtime configuration or source references these paths. Remove only their .gitkeep files, not active fixtures/resources.
- README selects a deleted feature branch and has stale Stage 2–4 status/scenarios. Architecture lists absent classes/ports and future adapter areas that now exist. CODEX references deleted authoritative/verification docs. Integration misnames AiDiagnosisPort and confuses experiment metadata with injection. Frontend README lists obsolete containment UI. PROJECT_STRUCTURE omits Stage runners and current stage views. Historical ADR phase descriptions need explicit historical framing; ADR-027 must account for guarded automatic recovery.
